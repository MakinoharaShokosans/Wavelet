## 3. 详细测试场景表现

### 3.1 突发并发任务投递与线程池吞吐
- **测试逻辑**：模拟用户批量导入包含 50 首曲目的文件夹，前端在毫秒级内同时下发 50 个分析/转码任务。
- **调度表现**：
  - 任务被异步调度器迅速吸纳入队，并按照 CPU 核心限制分批并发吞吐。
  - 避免了无节制创建 OS 线程导致的内存与 CPU 句柄耗尽崩溃。
  - 50 个任务全部在规定时间内计算完成，未发生任务丢弃或挂起。

### 3.2 SQLite 预写日志 (WAL) 并发读写韧性
- **并发冲突场景**：在没有传统多连接连接池的轻量级单文件嵌入式架构下，50 个操作同一时间向 SQLite 发送写（`INSERT INTO tracks`）与读（`SELECT ... WHERE keyword LIKE`）请求。
- **WAL 表现**：
  - 由于启用了 `journal_mode = WAL` 与 `synchronous = NORMAL`，读操作完全不阻塞写操作，写操作亦不阻塞读操作。
  - 数据库外键与唯一索引约束未触发任何 `SQLITE_BUSY` 或锁超时异常。
  - 最终数据核对结果显示插入记录数与预期 25 条完全吻合。

### 3.3 双专轨流式日志容量硬锁防爆盘
- **约束机制**：系统通过 `rotating-file-stream` 配置了双专轨日志：
  - 系统核心轨：`~/.wavelet/logs/wavelet.log`（单包 $\le 10\text{MB}$，最多保留 3 个归档）
  - 体检自愈轨：`~/.wavelet/logs/inspection.log`（单包 $\le 10\text{MB}$，最多保留 3 个归档）
- **容量监控**：持续注入高频压测日志，触发文件尺寸到达 10MB 时，自动压缩轮换，历史最早日志被自动擦除，磁盘占用严格被物理锁定在 30MB 额度之内，彻底避免了服务端常年运行日志打爆系统盘的常见故障。

## 4. 结论与判定
系统在极端高并发冲击、多线程争用与磁盘压力测试下保持了绝对的系统稳定性与数据完整性，韧性评测完全达标。
