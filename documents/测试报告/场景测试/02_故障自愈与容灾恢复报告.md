## 2. 故障自愈与容灾设计原理

Wavelet 作为本地守护式发烧级音乐引擎，遵循“**绝不崩溃退出、永不向外部抛出致命错误、零破坏宿主环境**”的容灾三原则：
1. **配置自愈机制**：当配置文件被意外改动、恶意篡改或格式损坏时，系统按小节校验并模块化回退至安全默认值，并覆盖写回磁盘完成修复。
2. **启动残留自洁**：系统若被 `kill -9` 强杀或遭遇硬件断电，在下次冷启动阶段由 `IntegrityGuard.cleanTempDirectory()` 扫描并全量清空 `~/.wavelet/cache/temp/`，防止磁盘爆满。
3. **安全隔离区 (Quarantine)**：对于不可逆损毁或恶意二进制伪装文件，禁止其进入曲库和转码管道，自动移交 `~/.wavelet/quarantine/` 并输出结构化审计日志。
4. **曲库物理失联容灾**：当外部磁盘被拔出或文件被删除时，系统不抛出文件异常，仅标记曲目为 `missing`，保留歌单架构。

## 3. 详细故障注入与自愈实测记录

### 3.1 场景 1：本地配置文件字段投毒与格式损坏自愈
- **故障注入**：向沙箱的 `config.json` 写入破坏性字段（非法类型、负数端口 `-9999`、非法 buffer 大小）。
- **系统表现**：
  - `loadConfig()` 捕获到 Zod 校验异常，启动按小节模块化自愈补齐机制。
  - 端口安全修正为 `23333`，缓冲区大小修正为 `4096`。
  - 将修复后的合法 JSON 配置回写磁盘，保证后续读取正常。
  - 进程无任何未捕获异常退出。

### 3.2 场景 2：异常断电产生的临时切片碎片自愈清理
- **故障注入**：在沙箱 `cache/temp` 目录下人工放置 3 个模拟上次异常崩溃遗留的临时切片。
- **系统表现**：
  - 调用 `IntegrityGuard.cleanTempDirectory()` 执行扫描。
  - 成功定位并原子删除 3 个残留垃圾文件（`cleanedCount: 3`）。
  - `temp` 目录文件数归零，彻底根除磁盘膨胀隐患。

### 3.3 场景 3：致命损毁文件（非音频/木马伪装）安全隔离
- **故障注入**：生成 1MB 随机不可逆乱码二进制，命名为 `trojan_virus_payload.flac`。
- **系统表现**：
  - 二进制嗅探器判定非音频魔数，初检输出 `canHeal: false` 与 `CorruptionType.LETHAL_CORRUPTION`。
  - 流水线安全阻断后续转码，将该文件复制归档至 `quarantine/` 隔离区。
  - 自愈流水线返回 `success: false`，记录详细隔离审计日志，绝不抛出非受控异常。

### 3.4 场景 4：曲库物理源文件丢失与断链容灾
- **故障注入**：在数据库预置一首曲目，但其 `filePath` 指向物理不存在的文件。
- **系统表现**：
  - `IntegrityGuard.auditMissingFiles()` 巡检检测到物理文件缺失。
  - 数据库曲目状态从 `healthy` 安全更新为 `missing`。
  - 用户调用曲目列表查询依然能正常返回该曲目信息，UI 正常渲染失联状态。
