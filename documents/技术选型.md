# Wavelet - 综合技术选型与技术栈决策规范

## 1. 选型原则与约束

Wavelet 定位为单用户本地运行的高性能音乐播放与资产管理软件，技术选型坚守以下四条工程准则：
1. **全栈纯 TypeScript**：统一前后端开发语言，在 Monorepo 体系下共享 DTO、领域模型与 WebSocket 事件契约。
2. **拒绝盲目造轮子**：对于通用标准化底层能力（SQLite 驱动、音频元数据反序列化、FFT 变换、转码工具链等），直接引入活跃度高、高星级的成熟轻量库；自研精力专注投入于**音频自愈流水线**、**发烧硬件直通调度**与**流体贝塞尔视觉**。
3. **零外部服务依赖**：摒弃 Docker、Redis、PostgreSQL、微服务等运维负担；采用进程内嵌入式 SQLite 单文件数据库。
4. **冷启动与常驻内存约束**：冷启动耗时 $< 200\text{ms}$，待机常驻内存 $\le 35\text{MB}$，所有大文件处理严格采用流式管道（Stream Piping）。

## 2. 全栈技术选型总览

| 层次 / 功能领域 | 推荐选型 | 备选对比 | 裁决原因 |
| :--- | :--- | :--- | :--- |
| **工程管理** | **pnpm Workspaces** | npm / yarn | 符号链接硬链存储，节省磁盘占用；严格隔离幽灵依赖；Monorepo 原生支持良好。 |
| **前端框架** | **React 19 + TypeScript** | Vue 3 / Svelte | 生态成熟，并发渲染控制精细，与状态管理和动效生态深度契合。 |
| **前端构建** | **Vite 6** | Webpack / Rspack | 毫秒级 HMR 热更新，开发体验顺畅，打包体积高度紧凑。 |
| **样式方案** | **Tailwind CSS v4** | CSS Modules / Emotion | 零运行时 CSS，编译期生成原子类，精准控制纯白无彩色主题与超椭圆圆角。 |
| **前端全局状态** | **Zustand** | Redux Toolkit / Pinia | 体积仅 ~1.2KB，无 Context Provider 嵌套，微秒级精确订阅避免高频重绘。 |
| **图标体系** | **Lucide React** | React Icons | 几何线框设计，支持 Tree-shaking，风格统一。 |
| **流体波形绘制** | **原生 Canvas 2D + Bézier 插值** | Three.js / Pixi.js | 杜绝 3D 引擎的高显存和数十兆打包体积；Canvas 2D 上下文每秒 60 帧平滑拟合流体曲线。 |
| **歌词解析器** | **`lrc-parser`** | 自行手写正则 | 成熟处理标准 `[mm:ss.xx]`、多时间戳复用标签与非法行容错。 |
| **后端运行时** | **Node.js LTS (v20+)** | Bun / Deno | 本地音频硬件 C/C++ 原生模块（`better-sqlite3`, `audify`）跨平台兼容性最稳固。 |
| **后端构建工具** | **`tsx` (开发) + `tsup` (打包)** | ts-node / tsc | `tsx` 零配置秒级启动；`tsup` 基于 esbuild，单文件摇树优化打包。 |
| **HTTP / WS 网关** | **Fastify + `@fastify/websocket`** | Express / NestJS | 高性能低开销路由，原生 TypeScript 支持，内建流式传输优化。 |
| **本地持久化** | **`better-sqlite3`** | `sqlite3` / Prisma | C++ 同步绑定，无 EventLoop 排队开销，读写速度极快；默认支持 WAL 模式。 |
| **元数据解析** | **`music-metadata`** | `taglib2` / `ffprobe` | 纯 TS 实现跨平台流式解析，支持数十种音频容器，秒级提取标签与内嵌封面。 |
| **二进制格式嗅探** | **`file-type`** | mime-types | 基于前 32 字节 Magic Bytes 检测真实文件类型，拦截伪造后缀。 |
| **转码中间件** | **`ffmpeg-static` + `fluent-ffmpeg`** | 纯 JS 解码器 | 经过广泛验证的工业级多媒体工具链，静态单二进制打包，转码兼容性强。 |
| **频域变换 (FFT)** | **`fft.js`** | `dsp.js` / 手写 DFT | 体积仅 2KB，基于基-4/基-2 优化算法，支撑 60fps 频谱分析计算。 |
| **声卡硬件直通** | **`audify` / `node-speaker`** | 浏览器 Web Audio | 原生 C 绑定，支持 Linux ALSA Direct 与 Windows WASAPI Exclusive 独占直通。 |
| **配置管理** | **`zod` + 双层存储架构** | dotenv / convict | 运行时强类型校验；引导配置用 JSON，高频交互偏好存入 SQLite `settings` 表。 |
| **结构化日志** | **`pino` + `rotating-file-stream`** | winston / log4js | 高性能异步流写入，待机内存 < 2MB；单文件 10MB 轮转压缩，最多保留 3 个历史备份。 |
| **代码规范与测试** | **Biome + Vitest** | ESLint + Prettier + Jest | 单二进制快速检查与格式化；Vitest 原生支持 TS ESM 单元测试。 |

## 5. 轻量化与防膨胀约束

在开发与迭代过程中，所有代码变更需满足以下刚性约束：
1. **依赖准入**：新引入 NPM 运行时包体积不超过 5MB（排除多媒体静态二进制文件）。
2. **纯 TS 规范**：严禁使用 `any`，杜绝滥用非空断言（`!`）。
3. **单进程优先**：日常播放与交互保持在单 Node 进程，重型计算仅在转码时按需唤醒 Worker 线程池。
4. **流式优先**：严禁全量一次性读入超过 5MB 的音频文件，统一通过 `Stream` 与固定大小环形缓冲区处理。
5. **本地存储隔离**：本地持久化数据严格集中于 `~/.wavelet/` 目录，单数据库文件 `wavelet.db`，日志总量严格限制在 30MB 以内。
